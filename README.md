# 联合模型 vs 专用模型对比实验汇报

2026-10-21

> 其他页面：[课题总进度与待办](progress.md) · [数据集介绍与样例](datasets.md)

## 一、实验目的与设置

结论先行：共享主干对巢房定位有正迁移，对蜜蜂检测和巢房内容分类有负迁移；DINOv3 联合模型在蜜蜂、王台、内容分类上最好，YOLO26s 在巢房定位上最好且速度快约 1.6 倍。

**要回答的两个问题**

1.  同一个模型做多个任务（联合模型），是否比每个任务单独训练一个模型（专用模型）差？
2.  主干选择的影响：YOLO11s、YOLO26s（CNN）与 DINOv2-S、DINOv3-S（ViT）。

**模型结构**：硬参数共享多任务学习，即“一个共享主干 + 每个任务一套专属参数”。

| 部分                                       | 内容                                                                                                               |
|--------------------------------------------|--------------------------------------------------------------------------------------------------------------------|
| 共享主干                                   | YOLO11s / YOLO26s 第 0–10 层；或 DINOv2-S / DINOv3-S（ViT-S + 简单特征金字塔，输出与 YOLO 主干同形状的三尺度特征） |
| 检测任务专属分支（蜜蜂、巢房、王台各一套） | 颈部（第 11–22 层）+ 检测头 + 原生损失；YOLO26s 用自己的颈部、头和 E2E 损失                                        |
| 内容分类专属分支                           | 多尺度分类头（8 类：封盖、卵、蜂蜜、幼虫、花蜜、花粉、其他、空巢房）                                               |

**联合与专用的定义**：联合模型同时训练 4 个任务；专用模型用完全相同的代码、步数和数据，只打开一个任务。两者唯一的区别是主干是否被多个任务共享，因此对比是公平的。

**训练数据**（所有主干完全相同）

| 任务         | 训练数据                                     | 输入尺寸 |
|--------------|----------------------------------------------|----------|
| 蜜蜂检测     | Roboflow 箱内视频帧 1,718 张                 | 640      |
| 巢房定位     | DeepBee 标注转换的切片 700 张 / 6,899 个巢房 | 320      |
| 王台检测     | 1,037 张正样本 + 428 张负样本                | 640      |
| 巢房内容分类 | DeepBee 7r 图块 58,844 个 + 现场裁片 198 个  | 224      |

**训练协议**：固定 6,000 步，每步每个任务各取一批数据（蜜蜂 8、巢房 16、王台 8、内容 64），损失等权相加；AdamW，主干学习率 1e-4，其余 1e-3；500 步预热 + 余弦退火；混合精度；取最后一步，不按验证集挑选。共 4 个主干 × 5 组（1 个联合 + 4 个专用）= 20 组训练。

**评测**：每个任务都有内部测试集和从未参与训练的外部测试集。外部集已与训练数据去重：蜜蜂用 Roboflow hivemind（199 张 / 5,134 只），王台用 5 个 Roboflow 项目（152 张 / 343 个 + 600 张负样本），巢房用 DeepBee 官方测试集（10 张 / 30,133 个巢房，完整标注）。

## 二、结果汇总

联合与专用谁更好取决于任务和主干：巢房定位联合更好，蜜蜂和内容分类专用更好，且主干越强差距越小。

表中为每个任务最关键指标的“联合 / 专用”，都在从未参与训练的外部测试集上。

| 任务（指标）                           | YOLO11s       | YOLO26s           | DINOv2-S       | DINOv3-S       | 谁更好                                 |
|----------------------------------------|---------------|-------------------|----------------|----------------|----------------------------------------|
| 蜜蜂检测（hivemind AP50）              | 0.327 / 0.544 | 0.419 / 0.563     | 0.432 / 0.529  | 0.550 / 0.558  | 专用；DINOv3 上基本持平                |
| 王台检测（测试集 AP50）                | 0.738 / 0.789 | 0.792 / 0.810     | 0.805 / 0.565  | 0.857 / 0.869  | YOLO 上专用略好；DINOv2 上联合明显更好 |
| 巢房定位（DeepBee 官方测试集 F1@0.7r） | 0.781 / 0.701 | **0.818** / 0.753 | 0.784 / 0.686  | 0.724 / 0.716  | **联合**（4 个主干都不差）             |
| 巢房内容（DeepBee 官方测试集准确率）   | 0.805 / 0.900 | 0.826 / 0.897     | 0.842 / 0.842  | 0.876 / 0.896  | YOLO 上专用明显更好；ViT 上接近        |
| 参数量（联合 / 4 个专用合计）          | 18.1M / 34.4M | 19.6M / 36.0M     | 36.9M / 109.7M | 36.4M / 107.9M | **联合**                               |

|----------|---------|---------|----------|----------|

| 王台     | −0.051  | −0.018  | +0.240   | −0.012   |

## 三、蜜蜂检测

专用模型在 4 个主干上都更好，但 DINOv3 的差距很小：外部 hivemind AP50 联合 0.550，专用 0.558。YOLO11s 差距最大（外部 0.327 vs 0.544）。

联合模型在外部数据上掉得比专用模型多，泛化更差；主干越强，这个差距越小。

## 四、王台检测

DINOv3 在王台上最好（测试集 AP50 联合 0.857、专用 0.869），联合与专用基本持平；YOLO 主干上专用略好；DINOv2 的专用模型没有训练起来。

## 五、巢房定位

联合模型在 4 个主干上都不差于专用模型，YOLO 和 DINOv2 上明显更好（F1 高 0.06–0.10）。YOLO26s 联合模型最好，F1 0.818。

测试集：DeepBee 官方测试集 10 张图、30,133 个巢房，每个巢房都有标注。预测中心与真值中心距离不超过 0.7 倍或 1.0 倍巢房半径 r 记为命中，一对一匹配。格内为 P / R / **F1**。

| 主干     | 0.7r 联合                 | 0.7r 专用             | 1.0r 联合                 | 1.0r 专用             |
|----------|---------------------------|-----------------------|---------------------------|-----------------------|
| YOLO11s  | 0.955 / 0.660 / **0.781** | 0.944 / 0.558 / 0.701 | 0.964 / 0.667 / **0.788** | 0.965 / 0.571 / 0.717 |
| YOLO26s  | 0.986 / 0.699 / **0.818** | 0.973 / 0.614 / 0.753 | 0.989 / 0.701 / **0.820** | 0.980 / 0.618 / 0.758 |
| DINOv2-S | 0.961 / 0.662 / **0.784** | 0.959 / 0.534 / 0.686 | 0.970 / 0.669 / **0.792** | 0.971 / 0.541 / 0.695 |
| DINOv3-S | 0.982 / 0.573 / **0.724** | 0.975 / 0.566 / 0.716 | 0.986 / 0.575 / **0.727** | 0.984 / 0.571 / 0.723 |

-   差距全在召回：精确率两者都在 0.94–0.99，联合模型多找到 8–13% 的巢房（DINOv3 上差距很小）。
-   这推翻了之前“联合模型定位有问题”的判断。
-   短训练还没收敛，召回只有 0.53–0.70；此前长训练的 v6 模型在同一测试集上召回 0.953、F1 0.927，高于 DeepBee 原方法的 0.859。本表用于比较相对差距。
-   DINOv3 在巢房定位上比 YOLO26s 低约 0.09：它的 patch 是 16 像素，在 320 输入上特征图较粗，密集小目标吃亏（推测，尚未验证）。

## 七、模型大小与速度

联合模型的参数量是 4 个专用模型合计的 34–55%；ViT 主干的联合模型比 YOLO 大约一倍，慢约 2 倍。

| 主干     | 联合模型参数量 | 4 个专用模型合计 | 联合 / 专用合计 | 延迟：蜜蜂 640 输入 | 延迟：巢房 320 输入 | 延迟：内容 224 输入 |
|----------|----------------|------------------|-----------------|---------------------|---------------------|---------------------|
| YOLO11s  | 18.1M          | 34.4M            | 53%             | 10.6 ms             | 10.5 ms             | 5.7 ms              |
| YOLO26s  | 19.6M          | 36.0M            | 55%             | 14.7 ms             | 15.1 ms             | 5.8 ms              |
| DINOv2-S | 36.9M          | 109.7M           | 34%             | 28.0 ms             | 20.1 ms             | 15.1 ms             |
| DINOv3-S | 36.4M          | 107.9M           | 34%             | 24.1 ms             | 23.9 ms             | 17.7 ms             |

延迟为 batch=1、单个任务前向一次的时间，全部在同一块 RTX 3080 Ti 上测量。专用模型单任务的延迟和联合模型基本相同；联合模型的优势是只部署一个模型。

## 八、结论与下一步

**结论**

1.  **共享主干对巢房定位有帮助**：4 个主干上联合模型都不差于专用模型，YOLO 和 DINOv2 上 F1 高 0.06–0.10。
2.  **共享主干对蜜蜂检测和巢房内容分类有损失，但主干越强损失越小**：蜜蜂外部 AP50 的差距从 YOLO11s 的 −0.22 缩小到 DINOv3 的 −0.01；内容分类从 −0.10 缩小到 −0.02。说明负迁移主要来自小主干容量不够，多个任务抢同一套参数。
3.  **主干选择**：DINOv3 联合模型在蜜蜂、王台、内容分类上最好，但巢房定位比 YOLO26s 低 0.09，参数多一倍，慢约 1.6 倍。YOLO26s 在 YOLO 系里全面优于 YOLO11s，巢房定位最好。DINOv2 整体不如 DINOv3。
4.  **所有模型在外部数据上都大幅下降**（王台外部 AP50 只有 0.18–0.26），跨场景泛化是主要短板，对应老师提出的遮挡识别和 AI 生成数据方向。

-   定位不是瓶颈：联合训练反而提升定位（见第五节）；v6 模型在 DeepBee 官方测试集上定位召回 0.953，只漏约 5%。
-   主要错误来自分类：v6 模型找到的巢房中 15% 分错类，约占全部错误的四分之三。
-   分类不准的原因有两个：一是推理代码裁块大小与训练不一致（准确率 0.85 → 0.55），已于 2026-10-21 修复；二是共享小主干对内容分类有负迁移（见第六节）。

**局限**

-   本轮是受控的短训练（6,000 步），用于比较设置，绝对数值低于长训练模型。
-   每组只训练一次，关键对比需要补 2 个随机种子。
-   DINOv3 的 5 组在 RTX 3080 Ti 上训练，其余在 RTX 2080 Ti 上；训练协议相同，但结果不会逐位一致。DINOv3 权重来自 ModelScope 官方镜像，论文中需引用 DINOv3 论文并注明来源。
-   现场验证样本很少（内容分类 49 个，人工复核的现场巢房 82 个）。

**下一步**

-   给内容分类（及蜜蜂）更多专属参数，验证能否补回联合模型的差距
-   关键对比补 2 个随机种子
-   选定设置后长训练最终模型
-   大量蜜蜂遮挡下的识别实验
-   AI 增强 / 生成数据实验
-   扩充现场验证标注
